# Vanompp v1.1 — Bugfix Design (Not Responded + Port Spam)

**Date:** 2026-08-05
**Status:** Draft → Approved via brainstorming Q1-Q4 locked
**Prior:** v0.1.0 (graph 402 nodes, 51 tests)
**Source:** grilling Q1-Q4 + graphify query + ponytail Approach 1

## Summary

v1.1 fix 2 UX killer:
1. Window Not Responded 3-10s saat Start MySQL/Apache (sync blocking di Tauri main thread).
2. Modal port conflict spam increment 3306->3309->3310 tiap Stop All -> Start All.

Principle: Vanompp anti-bingung SMK kelas 10-11. Satu tombol = satu mental model. Tetap pakai {port} = pakai + ingat forever.

## Locked Decisions

- Q1: freeze = Tauri main thread blocking Command::output + thread::sleep loops.
- Q2: C hybrid A — smart persist + tetap forever. Stop All tidak reset port. No auto-increment drift.
- Q3: Q3-A async spawn_blocking via tauri::async_runtime::spawn_blocking.
- Q4: Y single button Tetap pakai {suggest} = Pakai & Ingat forever + chip reset manual.
- Persist: A localStorage + vanompp.toml di app root (bin/../).

## Architecture

### Async fix

JS invoke(start_service) -> Rust #[tauri::command(async)] -> tauri::async_runtime::spawn_blocking(|| original sync start_mysql/start_apache) -> return Ok immediately -> frontend polling refreshStatus 3s detect running.

check_ports stays sync (fast <50ms).

### Port persist

Flow:
- Start MySQL 3306 -> checkPorts(3306) -> free? no -> modal Port 3306 udah dipakai + button Tetap pakai 3309.
- Click Tetap -> write_persisted_port(mysql,3309) -> vanompp.toml + localStorage lock + start_service(3309)
- Next Stop All -> Start All -> read_persisted_ports() -> 3309 -> check 3309 free -> start direct no modal.
- suggest_next_free: if port locked in toml, skip suggest drift — return locked if free, else next free but does NOT auto-lock.
- ServiceCard badge: {port} (custom) x if port != DEFAULT (3306/8080). x click -> reset_persisted_port -> revert default + toast.
- Reset explicit manual only, no auto-revert.

Data: vanompp.toml (disk survival) <-> Rust config.rs <-> commands/services.rs <-> invoke <-> localStorage vanompp:ports <-> services.ts <-> ServiceCard/App/PortConflictModal
Single truth Rust toml, localStorage optimistic cache.

## Components

### Rust new utils/config.rs (~40 LOC, no toml crate)

- get_config_path(root) -> root/vanompp.toml (or .vanompp.toml fallback)
- read_persisted_ports(root) -> (Option<u16>, Option<u16>) parse key=value lines, ignore corrupt.
- write_persisted_port(root, name: apache|mysql, port: u16) read-modify-write atomic temp+rename.
- reset_persisted_port(root, name) delete line.
- Tests: roundtrip, reset, corrupt fallback.

### Rust mod commands/services.rs

- #[tauri::command(async)] on start_service, stop_service, start_all_services, stop_all_services.
- Inside: tauri::async_runtime::spawn_blocking(move || { original logic }).await.unwrap_or_err -> map to Result String.
- check_ports: if arg None use read_persisted_ports over DEFAULT for baseline.
- get_status: merge effective port from persisted file.
- New commands: get_persisted_ports, reset_persisted_port, set_persisted_port (use set for explicit reset flow).
- Register in lib.rs invoke_handler.

### Rust unchanged apache.rs mysql.rs

Still sync but called via spawn_blocking so non-blocking at Tauri layer.

### Frontend lib/stores/services.ts

- DEFAULT_APACHE=8080 DEFAULT_MYSQL=3306
- STORAGE_KEY=vanompp:ports type PersistedPorts { apachePort?, mysqlPort?, locked:{apache?,mysql?} }
- loadPersisted(), savePersisted(), isCustom(port, default), effectivePort()
- refreshStatus merge: store > localStorage persisted > default. If locked.mysql and mysqlPort free skip conflict.
- New fns: setPersistedPort(name,port,locked), resetPersistedPort(name)
- checkPorts still maps to ConflictInfo via toConflicts

### Frontend PortConflictModal.svelte

- Primary button: Tetap pakai {first.suggest} VOLT #E9FF70 fullwidth, dispatch useSuggest
- Secondary row: Buka error.log link + Tutup
- Title: Port {port} udah dipakai emoji
- No sekali aja option (YAGNI Q4=Y)

### Frontend ServiceCard.svelte

- badge chip port custom if port != DEFAULT
- x click -> resetPort(name) -> reset persisted + revert default + toast
- loading spinner existing

### Frontend App.svelte

- handleUseSuggest: savePersisted + toast Tetap pakai {port} Ingat terus ya
- polling 3s existing keep.

## Error Handling

- vanompp.toml missing/corrupt -> fallback defaults, warn log, no crash.
- Write fail -> fallback localStorage only, toast Gagal simpan port coba run as admin.
- Locked port occupied again (XAMPP on 3309) -> suggest next free 3310 but does not auto-lock, modal again Port 3309 yang kamu tetap juga kepake Coba 3310? Tetap pakai 3310
- spawn_blocking panic -> Err Indonesianify
- stop_all/start_all concurrent guard via loading store already.

## Testing

- Rust cargo test: config roundtrip, reset, corrupt_fallback, existing port tests keep (51+3)
- Manual: Start MySQL 3306 with XAMPP on -> modal 3309 -> Tetap -> Stop All -> Start All -> must NOT modal -> TaskMgr no duplicate mysqld -> custom chip x -> click x -> revert 3306.
- Not responded repro: click Start MySQL -> window title must NOT show Not Responding via Process Explorer check.

## Non-Goals YAGNI

- No Tauri event emitter (polling enough)
- No full settings page
- No toml crate dep (manual parser)
- No async for check_ports
- Apache custom chip bonus only if time, primary MySQL

## Migration from v0.1.0

- No DB migration. vanompp.toml created on first Tetap click. Existing users default 3306/8080 auto.
- localStorage old key not exist -> first run defaults.
